# Как добавить навык

## 1. Выберите задачу

Хороший навык решает одну повторяющуюся задачу и имеет понятный момент срабатывания. Не делайте навык «на всё».

Проверьте:

- Задача действительно повторяется?
- Агент без навыка ошибается предсказуемым образом?
- Можно описать процесс так, чтобы его можно было проверить?
- Нет ли уже похожего навыка в `skills/<category>/`?

## 2. Выберите категорию

`meta`, `engineering`, `study`, `writing`, `language`, `work`, `data`, `product`, `design`.

Если задача не подходит ни к одной, предложите новую категорию и объясните, почему она не дублирует существующие.

## 3. Создайте навык

```bash
npm run new -- my-skill --category engineering
```

Категория обязательна.

## 4. Заполните `SKILL.md`

Обязательный frontmatter:

```yaml
---
name: my-skill
description: What the skill does and when to use it. Include trigger words and contexts.
metadata:
  category: engineering
  version: "0.1.0"
  inspired-by: "source/repo or original"
---
```

Требования:

- `name` совпадает с именем папки.
- Только lowercase, цифры и дефисы; без `--` и без дефиса на концах.
- `description` до 1024 символов, содержит и «что», и «когда».
- Тело до 500 строк.
- Инструкции на английском, в императиве.
- Никаких секретов и персональных данных.

## 5. Добавьте детали

Если навык большой:

- `references/` — справочники, шаблоны, примеры.
- `scripts/` — детерминированные операции.
- `assets/` — файлы, которые используются в результате.

Ссылки на файлы делайте относительными от папки навыка и не глубже одного уровня.

## 6. Добавьте standalone-промпт

Если задача важная и нужна версия для чата без установки, создайте `prompts/<category>/<name>.md` с коротким самодостаточным промптом.

## 7. Проверьте

```bash
npm run validate
```

Валидатор проверяет:

- frontmatter, имя, категорию, длину описания и размер `SKILL.md`;
- ссылки на локальные файлы;
- дубликаты и пустые каталоги.

## 8. Протестируйте на реальных запросах

Придумайте 2–3 запроса, которые пользователь мог бы написать в чате. Проверьте:

- Навык срабатывает по описанию?
- Результат соответствует заявленному формату?
- Нет выдуманных фактов?
- Нет лишней работы, которую пользователь не просил?

## 9. Оформите изменения

- Обновите каталог `docs/CATALOG.md`, если добавили навык.
- Обновите `docs/SOURCES.md`, если использовали чужую идею или текст.
- Добавьте запись в `NOTICE.md`, если адаптировали сторонний материал.
- Сделайте коммит: `feat(skills): add <name>`.

## Чек-лист PR

- [ ] `npm run validate` проходит.
- [ ] Навык проверен на 2–3 реальных запросах.
- [ ] Нет секретов и персональных данных.
- [ ] Указаны источники и лицензии.
- [ ] README обновлён.
- [ ] Diff ограничен задачей.
